# ADR-0002：常驻生命体征监控、复盘简报与可恢复熔断器决策

- **状态**：已确认（Accepted）
- **日期**：2026-11-24
- **关联文档**：[04-review-briefing-and-hitl.md](../04-review-briefing-and-hitl.md)

## 决策清单

### D7. 生命体征条与复盘简报物理分离（Always-On HUD vs. Episodic Briefing）
- **决定**：将系统生命体征（Broker 双车道负载、单机内存水位、活跃子代理、Trust Ledger 实时盘口、熔断与 Inbox 计数）移出复盘简报，作为**长期常驻的确定性实时状态面**独立存在。
- **理由**：方便人类随时零成本监控系统运行状态，无需触发 LLM 简报合成或打扰无人值守流程；同时让复盘简报本身保持高度聚焦的数学密度。

### D8. 触发机制采用“按需拉取 + P0 Push Alert”
- **决定**：常规复盘由人类按需拉取；但针对 P0 级高杠杆中断事件（关键路径猜想 `L2` 证伪、全轨道阻塞停摆、关键路径熔断无替代路线、验证底座持续崩溃）启用带冷却去重的 **Push Alert** 主动提醒。
- **理由**：兼顾平时零打扰与重大拐点及时止损。

### D9. 简报采用双语并排呈现（Informal Math + Formal Signature）
- **决定**：对关键里程碑、前沿瓶颈、定义异味与决策收件箱条目，并排展示自然语言/LaTeX 数学表述与精确形式化签名（保留隐式参数与 typeclass，不展开 proof body）。
- **理由**：在保持 5 分钟可扫读的同时，避免抽象散文掩盖形式化定义中的微妙类型/假设陷阱。

### D10. Definition Smell 启用“可恢复的局部熔断器”
- **决定**：当某上游定义触发异味阈值时，仅对其受影响下游队列实施局部熔断（`TRIPPED`），完整冻结并保留队列状态、检查点与 CoW worktree，不销毁现场；支持人类拍板后经 `RESUME_AS_IS`（经 `HALF_OPEN` 探针无缝恢复）、`PATCH_DEFINITION` 或 `ARCHIVE_AND_PIVOT` 三条路径恢复。
- **理由**：既能第一时间止血防止单机算力空烧，又能避免误判导致已有工作状态丢失。

### D11. 简报按需留存，杜绝无人查看的周期归档噪声
- **决定**：仅在触发 P0 Push Alert 或人类主动查看时落盘留存简报及对应确定性 Fact Pack（存于 `.runtime/briefings/`）；仅当某次复盘产出人类 `ADR` 时，将其精简摘要与 Fact Pack 哈希随 ADR 纳入 Git。
- **理由**：避免长时间无人值守产生大量无用日志，同时保证每一次人工战略转向都有完整可审计的事实依据。
